The only generated part is the blog (see **Blog** below), which GitHub Pages builds with Jekyll on each push. There is no local build step, package manager, test suite, or linter. Git repo on `main`, pushed to the public GitHub repo `dadragon4/nikolascampos.com` (`gh` handles auth). Commits use the GitHub no-reply email `62844398+dadragon4@users.noreply.github.com`; keep personal emails out of commits.

**Deployment:** GitHub Pages publishes `main` (repo root) to https://www.nikolascampos.com about a minute after each push. `CNAME` is `www.nikolascampos.com` (since Oct 31, 2026), so the bare domain and the github.io URL redirect to www. HTTPS is enforced, and the Let's Encrypt certificate auto-renews. `CNAME` holds the custom domain; don't delete it. `_config.yml` excludes `CLAUDE.md`, `CHANGELOG.md`, `HOW-TO-POST.md`, `README.md` and the `plans/` folder (drafts and proposals), and Jekyll skips dot-folders like `.claude/` and `.github/`. Any new root-level Markdown notes file must be added to `exclude`, or it gets published. HTML files without front matter are copied unchanged. DNS is at Namecheap: four A records to `185.199.108–111.153`, `www` CNAME to `dadragon4.github.io`. Neocities is no longer used.

To preview, use the `site` config in `.claude/launch.json`. It runs `.claude/serve.py` on port 8000, a static server that sends `Cache-Control: no-store` so edits show on reload. It listens on the local network so a phone on the same Wi-Fi can preview at `http://<Mac's IP>:8000`, and it refuses any path with a hidden (dot) segment, such as `.git` or `.claude`, including URL-encoded ones. A plain alternative (browser caching applies) is:

```bash

```

## Structure

- Every page, including the posts in `writing/`, uses the same skeleton: `a.skip-link` (targets `#main`) → `.wrap` → `header.site` (name, `a.view-switch`, tagline, nav) → `<main id="main">` (optional welcome/ticker, `hr.rule`, content) → `footer.site`. Pages in `writing/` use `../` for all site links, the stylesheet, and the script.
- **The header, nav, footer, and `<head>` links are duplicated by hand in every page (10 top-level: `index`, `film`, `music`, `services`, `about`, `contact`, `photography`, `writing`, `blog`, `404`; each post in `writing/`; and `_layouts/post.html`).** A change to any of them means editing all of them identically. `desktop.html` has its own markup.
- The footer is a site map: `nav.sitemap` (`aria-label="Site map"`) with three columns, Site (Home, About, Contact), Work (Film, Music, Services) and Elsewhere (Desktop view, YouTube, Spotify), each an `h2` plus a `ul`, followed by the `©` line in a `<p>`. Writing and Blog are left out on purpose (personal side).
- **Two sides:** the classic site is the professional front door. The Desktop view is the personal side; Writing and Blog live there only (their pages still exist at the same URLs but aren't linked from the classic nav or home page).
- **Phone menu:** under 480px the nav collapses behind a Menu button. Each page's header has `<button type="button" class="nav-toggle" aria-expanded="false" aria-controls="site-nav">` (☰ icon + `.nav-toggle-label`) right after `a.view-switch`, and the nav is `<nav class="site" id="site-nav" aria-label="Main">`. The button shows and the nav folds away only with the `js` class on `<html>`. A one-line script in each `<head>` (just before the stylesheet) adds `js` right away, so the full nav doesn't flash on each page load, and removes it again at `load` unless `js/site.js` has added `nav-ready`. The `site.js` tag also has `onerror` that removes `js`. So if the script is missing, blocked or an outdated cached copy, the links still show. Keep the head script, the `onerror` and the `nav-ready` line in sync on every page. `js/site.js` toggles `nav.site.is-open`, swaps the label between Menu and Close, and closes it on Escape (returning focus to the button).
- Nav: Home · Film · Music · Services · About · Contact. "About" links to `about.html`, which holds only the long professional bio (`#about-bio`, four `p.intro` paragraphs). The home page's `#about` section holds the short professional bio. The personal About and the "How I built this site" story are Desktop-only (see Desktop theme). (The Interests page was removed on Oct 26, 2026.) The current page's link carries `aria-current="page"`. Writing pieces, `writing.html`, `blog.html`, blog posts, `photography.html` and `404.html` have no current nav item.
- **Photography is hidden (since Oct 31, 2026)** until it has photos: it's out of the nav and footer, `noindex`, `sitemap: false` in `_config.yml`, and `hidden: true` in the desktop `APPS` list (no icon or Start menu item). The page still exists. To bring it back, undo those and restore the Portfolio dropdown: `<details class="menu"><summary>Portfolio</summary><div class="menu-list">` with Film and Photography links (its CSS in `styles.css` and its JS in `site.js` are still there; the `<summary>` gets `class="current"` on those two pages).
- `services.html` is a work-in-progress list (`ul.services`, each `li` an `h3` plus `p`). `contact.html` shows Niko's email (`p.contact-email`, a `mailto:` link) plus YouTube and Spotify. Their wording was drafted by Claude as placeholders for Niko's own.
- Every page links `css/styles.css?v=N` and `js/site.js?v=N`. **Bump the matching `N` on every page (and in `_layouts/post.html`) after editing the CSS or the script**, or browsers keep serving the cached old copy for up to 10 minutes (GitHub Pages sends `max-age=600`). A stale `site.js` with new HTML is what broke the phone menu on Oct 31.
- Home, Music, and Film have a `.ticker` (a scrolling "now" line with a Pause/Play button) between the header and `hr.rule`. Home also has a static `p.welcome` above it. Ticker items are `<li>`s, and the list appears **twice**: the second `<ul>` is an `aria-hidden="true"` duplicate for the seamless loop. Edit both copies identically. CSS adds the `·` separators, and `js/site.js` handles the button and sets a constant speed. With reduced motion, the duplicate and button are hidden and the text is static.
- The home page's "Latest" section has one card per section (`data-latest="music.html"` etc.). `js/site.js` fetches that page and copies its first `ul.index > li` into the card, but only if that entry has a `<time datetime>` and an `.entry`. Otherwise the card's existing HTML (a fallback copy) stays. Refresh the fallback when the newest item changes. Once every card has refreshed, the script sorts the cards newest-first by their `<time datetime>`, moving only out-of-place cards (moving a card reloads its player). Keep the cards in newest-first order in `index.html` too, so the order is right before the script runs. On localhost, the script logs `[site]` warnings for failed fetches or unexpected markup. The fetch needs the site to be served over http, not opened as a file.
- `js/site.js` is wrapped in a `{ … }` block so its `const`s stay out of the global scope. Keep new code inside it.
- Every `<iframe>` needs a descriptive `title` (e.g. `Listen to IMPRESSIONIST on Spotify`, `Watch Waiting: A Short Film on YouTube`) and `loading="lazy"`. Don't put `width="100%"` on iframes (invalid HTML); CSS sets the width. The `allowfullscreen`/`web-share` console notices come from the providers' embed code and are harmless.
- Page titles follow `Section — Nikolas Campos`; the home page is `Nikolas Campos — Writer, Filmmaker &amp; Musician`. Every page has a `<meta name="description">`, then `link rel="canonical"` (always `https://www.nikolascampos.com/…`; the home page is `/`), Open Graph tags (`og:type/site_name/title/description/url`) and `twitter:card`, all kept in sync with the title and description. The home page also has Person JSON-LD: `jobTitle` "IT Support Specialist", `worksFor` Valencia College, `alumniOf` University of Central Florida, `knowsAbout`, and `sameAs` (YouTube @NikoCampos, Spotify artist `52hPa2MC1beHdclC4xQzx4`). Keep it in sync with the bios. New pages need the same set. `desktop.html` is `noindex`.
- SEO files: `robots.txt` (static) points to `/sitemap.xml`, which `jekyll-sitemap` generates on GitHub Pages (`url:` in `_config.yml`; `desktop.html` and `404.html` are excluded via `defaults`). `blog.html` pins `permalink: /blog.html`.
- `404.html` is served by GitHub Pages for any missing URL, so every link and asset in it is root-relative (`/css/...`, `/`). It is `noindex`.
- Film's list is `<ul class="index stacked">`: the date sits on its own line above the video instead of in a left column.
- Music, Film, and Writing pages share one list pattern: `<ul class="index">` → `<li>` containing `<time datetime="YYYY-MM-DD">` (shown as e.g. `Mar. 31 2025`) plus `<div class="entry">` (a link, Spotify iframe, or YouTube iframe, followed by an `.excerpt`). Newest entries go first. Keep `datetime` in sync with the visible date.
- Posts are `<article class="post">` with `h2.post-title` and `span.meta` (byline and date). Add the `verse` class (`<article class="post verse">`) for line-by-line poems, which centers them. Prose stays left-aligned. A new post also needs an entry in `writing.html`.

## Blog (Jekyll)

- Niko writes posts as Markdown in `_posts/YYYY-MM-DD-slug.md` with front matter `title`, optional `excerpt`, optional `verse: true`. His guide is `HOW-TO-POST.md`; keep it in sync with any change to the workflow. Drafts go in `_drafts/` (never published). Images go in `images/blog/` and are referenced as `/images/blog/name.jpg`.
- `_config.yml` sets `timezone: America/New_York` and gives every post `layout: post` and the permalink `/blog/:title.html` (so posts sit one level down and use `../` links, like `writing/`). `kramdown.hard_wrap: true` turns single line breaks into `<br>`.
- `_layouts/post.html` builds the meta and OG description from `excerpt`, or from the post text if `excerpt` is empty. It is the site skeleton plus `article.post` (meta date via `_includes/date.html`, which formats dates the site's way, e.g. `Aug. 1 2026`, `June 19 2026`) and an "All posts" link.
- `blog.html` has empty front matter so Jekyll runs its Liquid loop; it outputs the standard `ul.index` pattern, so the home page's Blog "Latest" card and the desktop Blog window work unchanged. **The local Python preview server shows `blog.html` as raw Liquid, and posts don't exist locally** (no Ruby/Jekyll here). To see real output, push a non-main branch: `.github/workflows/preview-build.yml` runs GitHub's own Pages builder (`actions/jekyll-build-pages`) and uploads the built site as an artifact named `site`. Its actions are pinned to commit SHAs (tag in a comment) with `persist-credentials: false`; update the SHA and comment together. Download it with `gh run download <run-id> -n site -D <dir>`, untar `artifact.tar`, and serve that folder.
- Markdown posts can contain `h2`/`h3`, lists, images, `hr`, blockquotes, and code; `styles.css` and `desktop.css` style them inside `article.post`.

## Desktop theme (`desktop.html`)

- An alternate Windows 7/"Aero"-inspired view of the site, with its own `css/desktop.css?v=N` and `js/desktop.js?v=N` (bump `N` in `desktop.html` after editing either). It doesn't load `styles.css` or `site.js`. Every regular page's header has `a.view-switch` ("Desktop view") linking to it; the desktop's taskbar and Start menu link back to `index.html`.
- **Windows mostly have no content of their own.** The exceptions are the Desktop-only texts in `desktop.html`: "About Me" (`<template id="desktop-about">`, Niko's personal, casual intro) and "About This Site" (`<template id="desktop-site">`, the story of building the site with AI). Their APPS entries use `template:` instead of `src`/`pick`. These keep the personal side different from the professional About text on `index.html` and `about.html`. Otherwise `js/desktop.js` fetches the regular pages and clones sections into windows, using the `APPS` list (`src` page + `pick` selectors, e.g. `music.html` → `#music`). Changing a regular page updates the desktop automatically. A new page needs an `APPS` entry, plus its id in the Start menu list if it should appear there. Blog is `blog.html` → `#blog` (crumb `Documents ▸ Blog`). Services (`#services`, briefcase icon) and Contact (`#contact`, mail icon) have icons and Start menu items too; their icons are original inline SVGs in `ICONS` like the rest.
- Links inside windows open other site pages as new windows (writing and blog posts open via `article.post`; a page without one, like Services or Contact, shows its `<main>` content, titled from its `<title>`; the crumb says Blog when the URL is under `/blog/`); external links open in a new tab; `mailto:` and other non-http links are left alone. Now.txt is built from the home page ticker items.
- Uses only original artwork (CSS gradients and inline SVG icons), no Microsoft assets. On screens under 640px, windows fill the screen.
- `css/desktop.css` uses container queries, which the W3C CSS validator wrongly flags as errors. `desktop.html` itself validates.

## Styling conventions (`css/styles.css`)

- Colors come from `:root` variables (`--paper`, `--ink`, `--ink-soft`, `--accent`, `--rule`, `--wash`, `--shadow`). Use these instead of new hex values. They are redefined for dark mode (`prefers-color-scheme: dark`) and `prefers-contrast: more`, so any new color must be a token with a dark value too. Every page head has `meta name="color-scheme"` and light/dark `theme-color` metas.
- Accessibility/performance media queries: `forced-colors` (current-page underline), `print` (hides nav, ticker, embeds), `prefers-reduced-motion` (ticker). In `desktop.css`, `prefers-reduced-transparency` swaps blurred glass for solid colors. `site.js` skips the Latest fetches when `navigator.connection.saveData` is on.
- Body text is `112.5%` (`106.25%` on phones), not px, so it follows the visitor's browser text-size setting. Serif body text in a 640px centered `.wrap`. Small uppercase monospace is used for `h2.section-label` and dates.
- Lists scroll with the page. Don't put them in a fixed-height or scrolling box.
- Embeds are styled by `src` in CSS: YouTube iframes become full-width at 16:9, and Spotify iframes get rounded corners. Don't add inline sizing styles.
- One focus style (`a`, `button`, `summary` `:focus-visible`: 2px `--accent` outline). Don't add per-component focus rules.
- One mobile breakpoint at `max-width: 480px`.
- All pages passed the W3C HTML and CSS validators on Oct 26, 2026. Re-check with `curl -H "Content-Type: text/html; charset=utf-8" --data-binary @page.html "https://validator.w3.org/nu/?out=json"`.
- Unused styles exist for `p.lede` (drop cap), blockquote, and pre/code inside posts.
